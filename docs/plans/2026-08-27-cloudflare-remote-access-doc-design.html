DSH Cloudflare
远程访问文档

把当前安全部署方式整理为公开、可复用、无个人信息的双语教程与静态配置模板。教程解释安全职责；模板只提供占位符，不接触任何真实凭据。

目标与非目标

目标

  • 记录 Browser、Cloudflare、Tunnel 与 DSH Host 的请求路径。
  • 提供 Cloudflare Tunnel、systemd 与 Cordis 配置模板。
  • 说明 enrollment、设备 token、浏览器 session 与本地 bypass。
  • 提供可重复的部署验证和回滚步骤。

非目标

  • 不提交生产域名、邮箱、账户标识、Tunnel ID 或 token。
  • 不实现会修改系统或读取凭据的安装脚本。
  • 不把 trusted-host 描述成身份认证。
  • 不承诺 MAC 地址绑定；浏览器设备凭据才是设备身份。

安全模型

Browser HTTPS
  → Cloudflare edge
    → Access policy on the exact enrollment path
      → outbound Cloudflare Tunnel
        → 127.0.0.1:3080
          → DSH device-auth for HTTP and WebSocket
  • DSH 只监听 loopback；服务器不开放应用端口。
  • Cloudflare Access 只负责首次 enrollment；DSH device token 保护其余应用流量。
  • --trusted-host 限制允许的 Host header，用于 DNS rebinding 与误暴露防护，不替代认证。
  • Tunnel token 由主机外部文件保存，权限设为 0600，systemd 仅引用路径。
  • HSTS 和 HTTP→HTTPS 规则按单一 hostname 限定，默认不启用 includeSubDomains 或 preload。

实施步骤

  1. 写双语教程，覆盖 prerequisites、部署、enrollment、验证、token rotation 与回滚。
  2. 添加四个只含通用占位符的静态模板。
  3. 把教程加入 website/docs.ts 的双语发布映射。
  4. 生成 translation pairing 元数据。
  5. 运行文档检查、链接检查、格式检查和模板语法检查。
  6. 扫描新增内容和 pending diff，拒绝个人邮箱、域名、用户名、绝对 home 路径、Cloudflare 标识或 token。

风险与回滚

主要风险是把部署示例误当成真实安全保证、模板中遗留生产值，以及 Cloudflare Access 与 DSH device-auth 的职责说明不准确。通过占位符检查、隐私扫描和实际认证语义对照降低风险。

本次变更只增加文档、模板与网站映射。回滚时删除新增页面和模板，并移除对应 manifest entry，不影响运行时与现有部署。
