1. 目标与非目标

目标

  • 用户可在 DSH 中显式创建一个没有 model 参与的 Human Terminal。
  • Human Terminal 与 DSH Agent 出现在同一套 Workspace 导航中。
  • 一个 Terminal 可以同时从 Web、手机和 Kitty 访问。
  • 浏览器断线和 DSH Host 重启不会终止 shell workload。
  • 桌面端允许 Agent conversation 与 Terminal 多 pane split，手机端保持单 focus。

第一版非目标

  • 不把 Human Terminal 注册成 core Agent。
  • 不把 Terminal byte 写入 Agent Session log。
  • 不导入用户默认 tmux server 中已有的 session。
  • 不解析 Codex 或 Claude TUI 为结构化 DSH conversation。
  • 不自动调用 Kitty remote control；只提供稳定 attach 命令。

2. 系统架构

Unified Workspace UI
├── Model Agent Actor
│   └── Session → Agent Loop → LLM
└── Human Terminal Actor
    └── Console → console-tmux → dedicated tmux server
                                └── tmux session
                                    ├── Web attachment A
                                    ├── Web attachment B
                                    └── Kitty native attachment

“Actor”是产品层的统一导航概念，不替换 core Agent 接口。Model Agent 与 Human Terminal 共享 Workspace、标题、打开、归档和 pane 布局，但各自保留独立 runtime、状态和 renderer。

现有 model-facing Terminal 继续由确切的 live Agent 持有。Human Terminal 走 Host-owned Console 能力，因此不会削弱 ctx.terminals 的 exact-owner、controlled prompt、exclusive send 或 tool result 语义。

4. tmux provider

专属 server

Provider 使用配置的 server name，例如 tmux -L dsh。它不读取或修改用户默认 tmux server，从而使 ownership、发现和终止范围明确。

一对一映射

每个 Console 对应一个 tmux session。用户仍可在该 session 内创建任意 window 和 pane，但 DSH 的归档与终止不会影响其他 Console。

恢复

DSH Host 启动时扫描专属 server 中具有完整 DSH user options 的 session，恢复稳定 Console identity。缺失或损坏 metadata 的 session 不会被接管或删除。

Attachment

每个 Web viewer 启动一个独立 tmux attach-session PTY。tmux 为新 Client 绘制当前完整屏幕，因此重连不依赖 raw byte replay。

明确配置

tmux executable、server name、shell、window-size policy、attachment idle TTL、输出窗口、最大 Console 数量和每 Console 最大 Web attachment 数量都由 Cordis plugin config 提供，不作为隐藏常量。

5. 核心数据流

创建 Human Terminal

Client 选择 New → Human Terminal 与一个已注册 Workspace。
Host 分配 ConsoleId 与 DSH-generated tmux session name。
Provider 在 Workspace path 创建 detached tmux session，并写入非敏感 metadata。
Provider 读回 metadata；只有验证完整后才把 Console 发布到列表。
Client 打开 Console，并用当前 xterm rows/cols 创建临时 attachment。

打开与重连

Client 请求 attach(ConsoleId, rows, cols)。
Host 签发 attachment identity 与 capability，启动独立 tmux Client PTY。
tmux 输出当前完整终端屏幕；xterm 随后接收增量 byte。
刷新、换设备或 attachment 过期后创建新 attachment；旧 Client detach，workload 保持运行。

归档与终止

Archive 写入 tmux metadata 后才从活动 Sidebar 隐藏。Restore 反向更新 metadata。Terminate 需要确认，并且只在 tmux kill-session 成功后从 catalog 删除；所有 attachment 通过 tmux Client exit 观察到终止。

7. 安全与故障

Human Terminal 是 remote code execution

所有远程发现、创建和 attachment 操作必须经过现有 device-auth ingress。每个 attachment 还使用独立 capability；知道 Console ID 本身不授予 attachment I/O 权限。

  • Provider 通过 argv 调用 tmux，不拼接 shell command。
  • 专属 tmux server 在 scrubbed environment 下启动；Web 与 CLI attach 禁止 tmux environment update。
  • tmux metadata 不保存 capability、device credential、token 或 key。
  • Attachment capability 只存在于 Host 与 Client 内存；Host 重启后旧 capability 失效。
  • Terminal output 不进入 Session log、telemetry 或 connection-wide broadcast。
  • 创建失败会 rollback 本次未发布的 tmux session；不会删除已存在的 session。
  • 外部 kill 显示为 “Terminal ended externally”；DSH 不猜测恢复一个已经不存在的 workload。
  • tmux 缺失或版本不满足要求时 provider 在加载期失败；没有 provider 的部署不显示 Human Terminal 入口。

tmux 原生允许多个 Client 同时输入。产品不声称存在 Kitty 可以绕过的独占 controller。默认共享尺寸策略采用显式配置的 largest，避免手机 attachment 缩小大屏 Kitty；该策略的几何取舍在 UI 中保持可见。

10. 已确认决策

  1. Human Terminal 是产品层一等 Actor，但不是 fake/no-model core Agent。
  2. 一个 DSH Human Terminal 对应一个独立 tmux session。
  3. 全部 Human Terminal 使用 DSH 专属 tmux server 管理。
  4. 第一版只管理 DSH 创建的 tmux sessions，不导入现有 sessions。
  5. 关闭或归档不 kill；显式确认 Terminate 才 kill tmux session。
  6. 同一 Console 可以同时被 Web、手机与 Kitty attach。
  7. 桌面端支持 split tree，手机端只 focus 一个 Actor。
  8. 第一版允许用户在 Human shell 内手动运行 Codex/Claude；专用启动模板后续独立增加。
  9. Console workload 退出后不保留已结束的导航条目；Client 关闭该 Console 的全部 pane，并折叠留下的 split。

决策依据记录在 tmux-backed Human Terminal actors Agent Note。被取代的单 PTY 方案保留为 rejected guardrail。

11. Console 退出收敛

目标与非目标

Ctrl-D、exit、网页确认 Terminate 或外部终止 tmux session 都使对应 Human Terminal 从活动界面消失。关闭视图不会主动 kill workload；Archive 继续只控制导航可见性，不触发 pane 清理。

Host 仍保留足够的 ended 状态来完成 attachment cleanup、区分外部结束并保证 lifecycle operation 可诊断。自动清理只改变 Client 的导航与 device-local pane layout，不删除 Session、其他 Console 或普通 tmux workload。

集中生命周期协调

Web attachment 观察到 tmux Client 进入 exited 或 failed 状态时，让当前 renderer 进入 ended phase 并立即请求一次 catalog refresh；没有打开 Web pane 时，配置的周期 refresh 负责发现外部结束。
ui-console 只把 running Console 投影到活动或归档导航，并在 catalog 进入 ready 状态后把 running Console id 集合交给 layout。
layout 原子删除所有不在该集合中的 Console leaf；同一 Console 出现在多个 split 时一次全部删除，并递归折叠只剩一个 child 的 split。
active pane 被删除时选择一个存活 leaf；没有存活 pane 时清空 active pane，并让窄屏 Client 返回统一 Session 列表。

TerminalPane 只报告 attachment 已结束，不直接操作自己的 pane。这样一次生命周期事件可以同时清理 Sidebar、当前 pane、同一 Console 的其他 split，以及浏览器恢复出的 stale Console leaf。

  • 纯 pane tree 测试覆盖同 actor 多 leaf、嵌套 split collapse、active pane 存活与空 tree。
  • layout store 与 service 测试覆盖一次 reconciliation、手机列表 fallback、Agent pane 不受影响和 archived running Console 保留。
  • Console UI 测试覆盖 attachment ended 的即时上报、ended row 隐藏、初次 ready 清理 stale leaf、显式 Terminate 与周期 refresh 路径。
  • assembled Web snapshot 通过真实 xterm Ctrl-D、exited attachment 与 Host catalog 路径证明 row 和全部 pane 同时消失；真实 tmux canary 只验证部署重启后的存活性，不执行退出或终止。

主要风险是 catalog loading/error 被误判为资源消失。layout reconciliation 只接受 ready catalog；connection reset 与 refresh error 保留现有 pane。实现可通过移除 ui-console 的 reconciliation subscription 回滚，Host workload 与 tmux metadata 不需要迁移。

12. 实施计划

交付目标

交付一个可在 shipped Web composition 中创建、列出、打开、归档、恢复和终止的 tmux-backed Human Terminal；同一 Console 可被多个 Web attachment 和原生 Kitty tmux Client 同时访问；桌面端可把 Agent 与 Terminal 放入 split tree，手机端继续保持单 Actor focus 与 Browser Back 导航。

明确非目标

  • 本次不把 Human Terminal 接入 Agent Loop、模型选择、Session log 或结构化 conversation。
  • 本次不导入、重命名或终止用户默认 tmux server 中的 session。
  • 本次不提供 Codex、Claude 或其他 TUI 的专用启动模板；用户在 shell 中手动启动。
  • 本次不跨浏览器同步 pane layout，也不实现 pane drag-and-drop；只实现 split、resize、focus 和 close。

实现取舍

  • tmux metadata 使用一个 versioned、base64url-encoded JSON user option，包含 ConsoleId、WorkspaceId、标题、创建时间与 archived 状态；读取时整体校验，避免多个 option 的部分写入被误认为完整记录。
  • tmux session name 使用 DSH 生成且可严格校验的前缀与 UUID；ConsoleId 是对外身份，session name 是 provider 内部定位信息。
  • 每个 Web attachment 启动一个独立 tmux attach-session -E PTY。重新 attach 依靠 tmux 重绘当前屏幕，不把历史 raw byte 当作 durable terminal state。
  • Console catalog 在每次 mutation 后立即刷新，并用可配置低频 reconcile 观察外部 kill；terminal byte 继续只走 attachment long-poll。
  • pane tree 是 device-local 的 versioned discriminated union。恢复时整体校验非法数据；ready catalog 会自动移除已结束或不存在的 Console leaf，并折叠对应 split。
  • xterm 使用官方维护的 @xterm/xterm 与 @xterm/addon-fit；Terminal UI package 独占 xterm 生命周期、fit、输入编码与手机辅助键。

分阶段实施

  1. Console Service Definition。先写失败测试，定义 ConsoleAttachmentId、Attachment capability、durable snapshot、catalog、create/rename/archive/restore/terminate 与 attach/detach/I/O 接口；更新 JSDoc、invariant、subsystem docs 和消费者编译面。
  2. tmux metadata 与命令适配器。先测试 metadata round-trip、损坏/未知版本拒绝、安全 session name 和 argv；实现无 shell interpolation 的 tmux runner、可执行文件与版本 load-time 检查。
  3. tmux workload lifecycle。以独立 test server 写真实集成测试，随后实现扫描恢复、事务创建、rename、archive/restore、external-kill reconcile、confirmed terminate；Host dispose 只停止 reconcile 并 detach Web Clients。
  4. Attachment lifecycle。先覆盖 capability 隔离、并发 attachment、有界输出、wait cancellation、resize、TTL 与 teardown quiescence，再通过 spawnTerminal 启动独立 tmux Client PTY。
  5. Remote 与 Client runtime。先扩充 Typert RPC contract 和 foreign/stale capability 测试，再实现 catalog mutation、attachment long-poll、重连与显式错误投影；capability 不落盘。
  6. 原生 CLI。扩充 args 与 built-bin 测试，实现 console list/attach，复用同一 metadata codec；attach 前校验 ConsoleId、专属 server 和 TMUX，成功时让 tmux Client 接管当前 Kitty split。
  7. xterm UI plugin。安装官方依赖并先写组件生命周期测试，实现 fit/resize、raw input、paste、detach/reopen、状态 header、错误态和手机 Esc/Tab/Ctrl/方向/中断键栏。
  8. 统一 Actor 导航。给 Sidebar New 与 Workspace rows 增加 plugin slots；内建 Agent action 保持原行为，ui-console 贡献 Human Terminal 创建、row 与 lifecycle 菜单。
  9. 地址化 renderer 与 split canvas。先让 renderer 测试证明两个显式 SessionId 不共享 scope/store，再实现 ActorRef、split tree、active pane、Split Right/Down、divider resize、close、device-local persistence；mobile projection 只渲染 focused leaf。

  11. 产品验收。增加真实 runnable Web snapshot，覆盖 New 菜单、统一列表、Agent + Terminal splits、mobile Back、reconnect 与 terminate confirmation；在实际服务上创建 canary Console，从 Web 与本机 tmux 同时 attach，最后执行 privacy/secret scan。

13. 交付结果

产品行为

  • Human Terminal 已作为独立 Console actor 接入 shipped Web composition，不伪装成 core Agent，也不触发 model 或 Agent Loop。
  • 每个 Console 由专属 tmux -L dsh server 中的一个 session 持有；Web viewer 使用独立临时 attachment，本地 Kitty 使用原生 tmux Client。
  • Agent 与 Console 共用 Workspace 导航和 pane tree；桌面支持 Split Right/Down 与 resize，窄屏保持单 actor focus 和 Browser Back 返回列表。
  • Ctrl-D、exit、显式 Terminate 或外部 tmux 终止会在 Host catalog 确认后自动移除导航项与该 Console 的全部 pane，并折叠残留 split。
  • dsh console list 与 dsh console attach 已进入 built CLI；nested tmux attachment 会明确拒绝。

部署状态
