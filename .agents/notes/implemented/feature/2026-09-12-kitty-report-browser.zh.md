# Agent Note: Kitty report Browser

Status: implemented

[English](2026-09-12-kitty-report-browser.md) | 中文

## 问题

手机需要打开终端中的本地报告链接，同时保留所选 Kitty 终端。沙箱报告具有不透明来源，iframe 直接请求无法满足 DSH 的 Origin 和 Cookie 检查。若在 DSH 来源下运行报告脚本，报告代码便能访问应用。

## 决策

[Kitty 插件](../../../../plugins/kitty/README.zh.md) 通过 `shell.overlay` 打开右侧浏览器，保留[原生终端窗格](../architecture/2026-09-07-native-plugin-pane-rendering.zh.md)。桌面调整宽度和手机滑动关闭都保留终端选择与草稿。小窗维护报告历史；外层浏览器历史在离开终端前先关闭小窗。仅当前文档保留处理后的 HTML，历史只保存地址与访问限制。

已认证父页面请求 JSON，并将处理后的 HTML 放入不带 `allow-same-origin` 的沙箱 `srcDoc` iframe。parse5 和 css-tree 将范围内的静态资源转换为 data URL。每份文档的独立消息通道和 iframe 来源检查让链接、GET 表单和只读 fetch 经由父页面处理。每次 Host 请求都经过设备认证和 Connection 检查，没有绕过它们的报告 HTML 路由。可配置字节预算容纳报告内嵌图表并计入序列化开销；仅限制根文件会让资源展开量失去约束。文件缺失与大小超限采用不同界面提示。

显式点击终端链接或提交地址会选择真实文件目录或 HTTP 来源。Host 签发的限制仅由父页面持有，约束所有报告自动导航与读取。文件读取检查已打开的 Linux 文件描述符仍指向所选目录内的常规文件；HTTP 重定向保持所选来源。Host 限制资源数、字节数及并发量，卸载时等待取消的读取结束。

## 考虑过的替代方案

**单独标签页或直接文件链接**会让手机访问依赖手机文件系统，并将报告与终端草稿分开。小窗保留所需的本地报告工作流。

**使用 token 认证的资源 URL**可让 iframe 直接加载资源，但会引入带凭据的 URL 和另一条认证路径。父页面通过 JSON 复用 DSH 现有请求检查，并让可执行报告内容离开应用来源。

**每个 iframe 链接创建新范围**会让报告代码伪造导航，读取无关主机文件或服务。只有父页面上的显式操作可以选择其他目录或来源；自动导航复用当前限制。

**正则重写和透明网页代理**分别会遗漏合法 HTML/CSS 语法，或需要更广泛的 Cookie、写操作与流式传输语义。基于解析器的处理支持有大小限制的静态资源和只读请求，外部 CDN 引用仍由浏览器加载。

## 后果

本地报告保留脚本交互，无法访问 DSH 文档或凭据。内嵌资源带来 base64 开销，预览明确省略嵌套浏览上下文及完整网页应用代理。支持格式与限制由包 README 定义。真实 Loader/浏览器用例覆盖本地资源、fetch、iframe 隔离、受限导航、草稿保留、宽度调整和手机返回；聚焦 Host 用例覆盖认证、符号链接、重定向、FIFO 拒绝、取消与字节展开。
